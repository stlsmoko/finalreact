# Reel Reactor v1.0.12 Release Gate

This release candidate is **held**. It is not an instruction to build or install an APK. The goal is to distinguish code and deterministic-render evidence from physical Android evidence before any owner download occurs.

| Area | Code and deterministic evidence | Physical Android evidence required |
| --- | --- | --- |
| Source preparation | The picker copies native selections into app cache and resolves `ph://` iOS assets through Media Library before copying. The compositor rejects any unresolved `ph://` input instead of failing later in FFmpeg. | Choose local Android source clips from device storage and confirm the studio opens and source audio plays. |
| Bubble position and size | The studio and export now calculate the same contained-video rectangle. Tests cover a landscape source and command-level mapping. | Drag and pinch Bubble on portrait and landscape clips, then compare the export against the preview. |
| Pause and talk | Player time events provide the pause marker, duplicate/stale markers are normalized, and the composed timeline is not shortened by camera duration. A 4-second source plus a 2-second pause rendered to 6.010 seconds; two background crops during the pause had identical SHA-256 hashes. | Pause the source while speaking for 2–3 seconds, resume, and verify a visible freeze plus silence in the source track. |
| Source and reaction audio | The camera config requests audio recording, source monitoring uses the recording-compatible mix mode at 0.70 volume, and the final command retains source at 0.18 and reaction at 2.8. A camera file without an audio stream is rejected before composition; system FFmpeg rejected the same preflight with `Stream map '0:a:0' matches no streams`. The installed arm64 library exposes `alimiter`; reaction and final mix are limited to 0.95 and 0.96 respectively. | Confirm source monitoring is audible during record and speech is clear in the exported MP4. Use headphones to prevent speaker leakage from being mistaken for the recorded reaction. |
| Review audio | Review pauses its player when it loses navigation focus and before leaving via close or re-record, so the previous player cannot retain audio focus. | Enter review, play once, leave/re-record, and verify no second playback or audio track continues. |
| Green key | The selected green-key branch still reaches FFmpeg. | Use an evenly lit, bright green backdrop. Confirm only that green is removed; an ordinary room is not a chroma-key input. |
| Control dock | The dock is bounded, on top of the overlay, and contains its own scroll view. Overlay movement is constrained above it. | On the target small phone, scroll from the control-dock area and reach every button. |
| Android packaging | Expo configuration and clean Android prebuild succeed with arm64-only FFmpeg and the low-memory Gradle settings. | The platform build and install remain unproven because the sandbox Gradle daemon is externally terminated before task execution and no cloud log is accessible here. |

## Remaining release blockers

1. **Do not build v1.0.12 yet.** The release remains held at the owner's request while the audit record is reviewed. There is no unaddressed confirmed code defect from this audit, but code evidence is not phone evidence.
2. **No physical Android output has been inspected for v1.0.12.** Bubble geometry, source monitoring, reaction loudness, Green key, dock scrolling, review isolation, and pause export remain device-validation requirements.
3. **No standalone APK exists in this workspace.** Prebuild success is not APK success, and the historical platform build failure near 60 percent remains a packaging-platform issue until a fresh build card and log are available.
